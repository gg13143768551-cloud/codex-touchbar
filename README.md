# Codex Touch Bar

[![macOS](https://github.com/liumingshuo77-cmyk/codex-touchbar/actions/workflows/macos.yml/badge.svg)](https://github.com/liumingshuo77-cmyk/codex-touchbar/actions/workflows/macos.yml)

A native macOS companion that brings Codex quota, token usage, model controls, runtime health, and account profiles to the physical Touch Bar.

```text
[5h 72%] [7d 54%] [Today 84k] [GPT-5.6 ▾] [high ↻] [Ready] [↻ Work]
```

> [!IMPORTANT]
> This is a source-first preview. It uses Apple’s public `NSTouchBar` API, so the Touch Bar UI appears while the app’s Settings window is active; it does not inject controls into Cursor, Terminal, or other applications. The menu-bar interface remains available at all times.

[Features](#features) · [Build](#build-from-source) · [Account setup](#account-setup) · [Security](#security-model) · [中文说明](#中文说明)

## Features

- **Exact 5-hour and 7-day quota windows** — displays remaining percentage, reset time, and freshness without estimating local consumption.
- **Today’s token usage** — reads Codex’s server-provided daily usage buckets.
- **Dynamic model picker** — discovers models from `model/list` rather than shipping a stale hard-coded list.
- **Reasoning-effort control** — cycles only through effort levels supported by the selected model.
- **Live health state** — shows Ready, Working, Stale, Login required, Attention, or Offline.
- **One-touch account cycling** — switches between explicitly configured account profiles with rollback on failure.
- **Full menu-bar fallback** — all essential controls remain usable on Macs without a Touch Bar.
- **Local-first operation** — no telemetry, remote database, or conversation upload.

## How it works

Codex Touch Bar starts a local Codex app-server for the selected profile and communicates over JSONL stdio:

```text
Touch Bar / Menu Bar
        │
        ▼
   DashboardStore
        │
        ▼
 StableProtocolAdapter
        │
        ▼
 codex app-server ── CODEX_HOME=<isolated profile>
```

The implementation currently targets the app-server schema generated by `codex-cli 0.147.0`. Protocol decoding is isolated in `StableProtocolAdapter.swift`, and malformed or unsupported responses fail closed instead of being displayed as valid data.

Used methods:

- `initialize` / `initialized`
- `account/read`
- `account/rateLimits/read`
- `account/usage/read`
- `model/list`
- `config/read`
- `config/batchWrite`
- `turn/start`

For multi-bucket quota responses, the `codex` bucket is preferred. Only windows whose durations are exactly `300` and `10080` minutes are accepted as 5h and 7d.

## Requirements

- macOS 12 Monterey or later
- A MacBook Pro with a physical Touch Bar for Touch Bar controls
- Xcode 15.4 or later and Swift 5.10 or later
- Codex CLI with app-server support

Check Codex before building:

```bash
codex --version
codex app-server --help
```

## Build from source

```bash
git clone https://github.com/liumingshuo77-cmyk/codex-touchbar.git
cd codex-touchbar
bash Scripts/build-macos.sh
open .build/xcode/Build/Products/Debug/CodexTouchBar.app
```

The build script runs all Swift package tests and builds an unsigned Debug app. It does not modify your signing configuration.

To sign an existing build with your own Developer ID:

```bash
CODEX_SIGN_IDENTITY='Developer ID Application: Your Name (TEAMID)' \
  bash Scripts/sign-macos.sh .build/xcode/Build/Products/Debug/CodexTouchBar.app
```

Signing is not notarization. Distribution outside your own Mac still requires Apple notarization.

## Account setup

1. Start Codex Touch Bar and open **Settings** from its menu-bar icon.
2. Select the Codex executable if it was not discovered automatically.
3. Add a profile such as `Personal` or `Work`.
4. Select that profile and click **Start official Codex login…**.
5. Repeat for additional accounts.
6. Enable **one-touch account switching** after every profile is authenticated.

Each profile owns a separate directory:

```text
~/Library/Application Support/CodexTouchBar/Profiles/<UUID>/codex-home
```

Touching the account button validates the next profile’s app-server, authentication state, usage data, and exact `CODEX_HOME`. Only after validation succeeds is the selected profile committed. A failed switch leaves the current account untouched.

### Account-switch boundary

Switching changes the profile monitored by Codex Touch Bar and the configuration used by future sessions launched with that profile’s `CODEX_HOME`. It does **not** log out, terminate, or hot-swap an already running Codex process in Cursor or Terminal.

## Model and effort changes

Model and effort changes are written together with `config/batchWrite`, followed by `config/read` verification. If the write response is lost, the app performs one authoritative readback and never blindly retries the write.

Changes apply to future threads and turns. An active turn keeps the model and account with which it started.

## Token date boundary

`account/usage/read` in the 0.147.0 schema returns dated daily buckets but no timezone. When no service date or timezone is provided, the app selects the current UTC bucket and labels the assumption in the UI tooltip. It never reconstructs account-wide token usage from local session logs.

## Security model

- Credential file contents are never read, copied, parsed, displayed, or logged.
- Login uses the official `codex login` flow inside the selected profile’s `CODEX_HOME`.
- Known inherited API-key/access-token environment variables are removed from profile child processes.
- Profile directories use `0700`; metadata and caches use `0600`.
- Codex is launched with `Process.executableURL` and argument arrays, never through a shell.
- Configuration and selected-profile writes are atomic and verified by readback.
- Logs contain method names, sanitized error codes, versions, and timing only—not RPC payloads.
- There is no telemetry or remote synchronization.

## Status and stale data

- Quota or usage data older than 2 minutes is marked stale.
- Quota values older than 10 minutes are no longer presented as current.
- A disconnected app-server reconnects with bounded exponential backoff.
- Poll results from an old account cannot overwrite a newly switched profile.
- Configuration controls are locked while a write or account switch is pending.

## Test and verification

On macOS:

```bash
swift test --package-path Packages/CodexTouchCore
bash Scripts/build-macos.sh
```

On Windows, where AppKit cannot be compiled:

```powershell
.\Scripts\verify-static.ps1
```

The repository includes domain, persistence, JSON envelope, protocol-contract, uncertain-write, reconnect, and account-switch tests. GitHub Actions runs the macOS build/test path and the Windows static verifier.

Physical rendering, browser login completion, signing, and notarization still require real Mac hardware and user-controlled accounts.


## Known limitations

- Public AppKit cannot provide a globally persistent Touch Bar surface over other foreground apps.
- There is currently no prebuilt, signed, or notarized release.
- Compatibility has been fixture-checked against Codex CLI 0.147.0; later protocol changes may require adapter updates.
- “Today” uses a visibly labeled UTC fallback when the server omits timezone metadata.
- Physical Touch Bar behavior cannot be fully validated by CI.

## Contributing

Issues and focused pull requests are welcome. For protocol changes, include a redacted generated schema or fixture and add a contract test. Never commit Codex credentials, authentication payloads, or real account identifiers.
